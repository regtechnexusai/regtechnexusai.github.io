METHOD · CONTROL DESIGN

Screening Methodology

A modular-monolith/API-first design for evidence-oriented sanctions screening.

Production data lifecycle

RawRetrieve the official source without overwriting the last valid version.
ValidatedValidate transport, schema, record counts and parsing integrity.
NormalizedPreserve original values and record transformation rules.
PublishedExpose only the latest valid version to the screening engine.

Core controls

  • Source-specific schedules, ETag/Last-Modified/hash checks, retry and manual refresh.
  • Source-version record containing source URL, retrieval time, content hash, parser version, schema version, effective/published date and validation state.
  • Candidate generation uses exact, token and edit-distance signals; transliteration/abbreviation expansion is candidate generation, not authoritative equivalence.
  • Similarity score is an explainability aid, not a sanctions probability or legal determination.
  • Final disposition is separate from the screening result and belongs to a human reviewer.
  • Source failure, stale data or parser failure must produce Screening Incomplete, never “No Match”.
  • PEP/RCA and adverse media are separate risk-intelligence layers and must not be conflated with sanctions status.
  • Public screening should not accept confidential customer data until appropriate access control, retention, privacy, encryption and audit controls are implemented.

Recommended production modules

Next.js UI → REST/JSON API → NestJS modular backend → Source Management / Screening Engine / Report Engine → PostgreSQL → Redis queue/workers → object storage for evidence reports.

Recommended tables: sanctions_records, sanctions_aliases, identifiers, source_versions, screening_requests, screening_results, review_decisions.

Evidence report minimum

Input, timestamp, sources checked, source version, source record ID, primary name, aliases, identifiers, matched/non-matched fields, matching method, engine version, review status, reviewer decision, evidence references and limitations.
